# mythril tests

Two tiers. Pure tests (everything in this folder except `gpu/`) check library logic exhaustively with no device and run anywhere. `gpu/` builds `mythril_gpu_tests`, which needs a Vulkan device (ctest label `gpu`, exits 77 to skip when there is none) and checks only what no pure test can see, such as push data reaching the shader where the generated struct put it, never barriers. Any validation layer message fails it (ctest `FAIL_REGULAR_EXPRESSION` on `[Validation]`, so it needs a build where logging and validation are on). The device tier is running the real samples under validation, which today lives outside the repo as a per-machine check. It is weak at barrier hazards: lavapipe executes close to serially, so a missing barrier rarely corrupts output, and syncval cannot see bindless or BDA accesses. So barrier coverage lives in the pure tier, a passing device test is never proof that a barrier is right, and a pure test is never proof that rendering is right. Tests build in any top-level configure (`MYTH_BUILD_TESTS` defaults to `PROJECT_IS_TOP_LEVEL`); run `ctest --test-dir build/debug`. Sync rules come from `vk_sync_tables.h`, generated from the SDK's `vk.xml` at configure time by `gen_sync_tables.py`; never hand-copy stage or access tables.

Every new pure sync test follows the shape of `test_buffer_barriers.cpp`:

1. Test the function the library actually calls. If the logic is composed inline in a `cmd*` method, extract it into a pure `vkutil` function first and have the method call it. Only do this for logic the samples run.
2. The oracle (what accesses are possible for a given input) is written from the Vulkan spec, never from the code under test. Failure example: an oracle built from `kBufferUses` would agree with it if a row dropped BDA shader writes.
3. Enumerate the whole input space through the same mapping the library uses (`ToVkBufferUsage` over every usage bit subset and storage type, every valid feature set) instead of picking examples, and check the case count so an empty loop cannot pass.
4. Never write a new checker. Describe the accesses and the barriers between them as `sync_spec::Step`s and call `sync_spec::Violations` (`sync_spec.h`). It checks validity against the vk.xml tables, that every hazard across steps is ordered (barriers in later steps chain, barriers in one step are one batch and do not), and tightness (every stage and access bit is justified by a hazard). ALL_COMMANDS, MEMORY_READ and MEMORY_WRITE are banned outright. Put the spec oracle and the enumeration in the test file, nothing else.
5. For each real bug the test is meant to catch, add an entry to `mutants.py` that puts the bug back into the real library code and names the test case that must fail. Run `tests/mutants.py` (about 80 seconds, `-k` runs a subset) after you change a sync test or `sync_spec.h`, and before you trust a new test. Every mutant must be killed. Never keep copies of old buggy code in the test sources.

Known limits of the pure tier: no queue family dimension (narrowed masks use graphics-only stages, fine while every `CommandBuffer` records on the graphics queue) and no feature gating beyond acceleration structures and ray tracing.

## Scope

Tests cover the code as it is and the inputs the samples actually produce. Never add or widen library functionality (new parameters, new result types, offscreen modes, sample hooks) just to make something testable. Extracting existing inline logic into a pure function the library then calls is fine. Add a test when a change is about to touch logic the samples run, or when a real bug is found.
